# Stage definitions scorecard (SC-01 to SC-10)

Scores the written definitions only, never individual deals. The ids are for this file only; in the answer, name each check in plain words. Each check is 0, 1 or 2, with a short quote from the user's text as evidence. Distinguish confirmed absence (0) from not-supplied evidence and not-applicable checks; do not score missing excerpts as proof the process lacks a rule. When a combined total is requested, it is out of 20 and labelled "checklist score, not a forecast of accuracy". For a request to score definitions, assess each active stage on exit-criterion presence, buyer-side evidence and a distinct gate (0 = absent, 1 = partly specified, 2 = explicit), report each stage out of 6 with evidence, labelled "buyer-gate checklist score, not a forecast of accuracy", and keep the other seven checks as supporting system checks. State that seller-only or duplicated gates need rewriting regardless of administrative completeness; a signed Closed-won definition does not make an active-stage gate buyer-side.

| Id | Check | 2 | 1 | 0 |
|---|---|---|---|---|
| SC-01 | Each stage has an exit criterion | every stage | most stages | few or none |
| SC-02 | Exit criteria are things the buyer did or confirmed (a meeting held, a budget named, a signed order form), not seller activity | all buyer-side | mixed | seller activity only |
| SC-03 | No two stages share the same exit criterion | none shared | one pair shared | several shared |
| SC-04 | Stated probabilities rise from one stage to the next | strictly rising | one flat step | a drop |
| SC-05 | Required fields are named per stage (amount, next step, expected close date) | named for each stage | some | none |
| SC-06 | A lost-reason list exists with a short fixed set of reasons | yes, fixed list | open text only | none |
| SC-07 | Rules for moving a deal backwards or reopening it are written | yes | implied | none |
| SC-08 | The point where a deal enters the pipeline (counts toward coverage) is defined | yes | vague | none |
| SC-09 | Definition changes are dated | yes | partly | no |
| SC-10 | Closed-won is defined by a document or event, not by opinion | yes | partly | no |

After scoring, prioritise documented definition weaknesses, especially seller-only or duplicate buyer gates. Give the requested number of one-line rewrites using the user's stage names; otherwise match the number to material defects. When no calibration table/flag exists, use definition evidence alone. A rewrite addresses a weakness; it does not establish the cause of a probability error.
