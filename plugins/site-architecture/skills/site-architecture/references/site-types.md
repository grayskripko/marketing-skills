# Site types: usual sections and where structure tends to break

Patterns, not quotas. Use them to ask better intake questions and to spot a missing section; never to impose a page count or a depth.

| Site type | Usual top-level sections | Sections that grow | Where hubs usually sit | Common structure problem |
|---|---|---|---|---|
| B2B software | product or features, solutions (by role or industry), integrations, pricing, customers, docs or help, blog, company | integrations, blog, docs, customer stories | features overview; solutions by role; integrations index | features split over two folders; one integration listed in two sections |
| Online shop | categories and subcategories, brands, offers, help, account | products, filter combinations | category pages; brand pages | filter URLs multiplying; products reachable only through deep pagination |
| Publisher or blog | topics, authors, series, about | articles | topic pages | date folders in URLs; tags duplicating topics |
| Documentation | getting started, guides, reference, changelog | reference pages, guides | guide indexes per product area | version folders duplicating pages; no single path to a page |
| Local service business | services, areas served, about, reviews, contact | service-area pages | services index | one page per town with the same text |
| Marketplace or directory | categories, locations, listings, sell or list with us | listings | category and location indexes | listing URLs that change with filters |

For a mixed site (software plus a large blog or docs), keep each part's own pattern and connect them through hubs rather than mixing folders.
