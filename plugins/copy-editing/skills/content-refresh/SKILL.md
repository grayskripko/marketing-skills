# Content refresh

- Change only what is dated. Every other sentence stays as written.
- Turn relative time into dates counted from the publish date: posted July 2024, "last year" becomes "in 2023".
- Use the user's new facts as given. Never use your own idea of a current value.
- A dated historical fact ("a 2023 survey found 72%") is still true as history. Keep it as is and do not ask the user to re-verify it.
- Remove recency words that are now wrong ("recently", "new") while keeping the fact underneath ("our new booking system" becomes "our booking system").
- A promise whose date has passed and whose outcome is unknown ("our laser cutter arrives this autumn"): take it out of the publishable text and tell the user, without guessing what happened.
- Give a text ready to publish, with no bracketed notes inside it. Then a short list of what changed and anything the user still has to confirm.
- Updated date: suggest a visible "Updated" line when a fact changed, not for wording tweaks. Keep the original publish date, and make any date in the page's structured data agree with the visible one.
- If given a URL, fetch only that page, and only if the site's robots.txt allows it. If that fails, ask for the text.
