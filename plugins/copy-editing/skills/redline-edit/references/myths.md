# Myths this plugin does not follow

| Belief | What the skills do instead |
|---|---|
| A proofread should make the text better. | A proof fixes slips and asks questions. Improving the text is a copyedit, done earlier and only when asked. |
| One careful read catches everything. | Separate passes per category, with a count for each, including zeros, so a skipped check is visible. |
| The serial comma, numerals and spelling variants have one right answer. | They are house choices. Until the user or a style sheet decides, they are listed, not changed. |
| A readability formula tells you whether text is good. | Sentence length and passives are reported as checks, not as a score or grade. |
| Refreshing a page means putting a new date on it. | A date line is advised only when a stale value was replaced or a section was added. |
| Editors should fill gaps with plausible details. | Gaps get a marker. Figures, names and dates come only from the user. |
| Em dashes show that a machine wrote the text. | Em dashes are punctuation. The skills do not remove them for that reason. |
| Consistency means changing every variant to the most common one. | Near-ties and words that may name two different things stay open for the author. |
| A different number in two documents is a typo to harmonise. | It is a fact conflict, reported with both locations, never averaged or picked. |
| Spell checkers make a proof unnecessary. | They pass correctly spelled wrong words (their for there) and cannot check a date against its weekday. |
| A published style guide must be chosen before editing. | The author's own consistent choices are a valid basis; a named guide is one option the user may pick. |
| Cutting means deleting adjectives. | The large savings come from repeated points and lead-ins; single words come last. |
