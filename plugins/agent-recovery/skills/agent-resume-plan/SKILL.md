# Plan a safe continuation

Give the ordered steps the user asked for, in their shape and length. Each step names what to check first and what proves it worked. Do not run, launch, send or replay anything; if the user said not to launch, prepare the command without telling them to run it.

- Keep finished files and receipted effects; never re-perform them. Copy any file or store the resume could overwrite before it runs.
- List every write that can run again from the chosen restart point and guard each one before it runs. Hold an uncertain write until an authoritative lookup for that exact request settles it. A new idempotency key cannot deduplicate the old attempt, so send again only after the lookup shows no effect, with a new key recorded before sending; an expired deduplication window gives no protection.
- Resume the saved state only when its identity matches the job; otherwise plan a fresh run that explicitly excludes completed work. A chat transcript is context, not a resumable checkpoint.
- When something must wait, give the safe move available now within the user's authority: a read-only lookup the records show exists, or preparing in a scratch location that does not overlap a live writer. Never make the held side effect itself the fallback, and never take a decision that belongs to the user.
- Reuse an existing approval for the exact pending call: compare that call's arguments with the approval record, and ask for a new approval only when the target, payload or scope changed. The approver decides; say what to verify before approving.
- Independent, already-authorized work can go first.
- For a named runtime, write the documented call with the user's IDs (below), not "check your version's docs".

Documented calls; use the one that fits, never list them:

- LangGraph: on resume the interrupted node restarts from its beginning. If a subgraph was invoked inside a parent node, that parent node restarts too, so every write before the interrupt in either node runs again. Nodes whose successful writes were saved are not re-run. Inspect read-only on the parent graph with `graph.get_state({"configurable": {"thread_id": <id>}}, subgraphs=True)`; a new `thread_id` starts an empty thread. <!-- docs.langchain.com LangGraph use-subgraphs and interrupts, checked 2026-10-15 --> Resume on the same `thread_id` with `Command(resume=<the user's decision>)`. Guard each rerunnable write with a check before it, or move it into its own node. <!-- docs.langchain.com/oss/python/langgraph/interrupts ; /checkpointers (pending writes); reference.langchain.com/python/langgraph/pregel/main/Pregel/get_state, checked 2026-10-15 -->
- Codex CLI: `codex resume <SESSION_ID>` resumes that session, given by UUID or name. `--last` picks the most recent session from the current directory, and `--all` drops that directory filter. Run it from the session's workspace or pass `-C <dir>`, and state the original sandbox explicitly. <!-- learn.chatgpt.com/docs/developer-commands?surface=cli (was developers.openai.com/codex/cli/reference), checked 2026-10-15 -->
- Claude Agent SDK: `continue` takes the most recent session in the current directory, and `resume` takes a session ID; the session file must be on the same machine. For another host, copy `<session-id>.jsonl` into `~/.claude/projects/<encoded-cwd>/` for the cwd you resume from, use a `SessionStore` adapter, or seed a fresh session with the saved results. Set allowed tools and permissions explicitly on the resuming call. <!-- code.claude.com/docs/en/agent-sdk/sessions.md (Resume across hosts), checked 2026-10-16 -->
- OpenAI Agents SDK Python: save with `result.to_state()` and `state.to_string()`. Restore with `await RunState.from_json(top_level_agent, json.loads(stored))` <!-- openai.github.io/openai-agents-python/human_in_the_loop/, checked 2026-10-15 -->, then call `state.approve(interruption)` on the exact interruption, then `await Runner.run(top_level_agent, state)`. Interruptions from an agent used as a tool surface on the outer run; resume the top-level agent. <!-- openai.github.io/openai-agents-python/human_in_the_loop/, checked 2026-10-15 -->
- Claude Code cloud session: when its container restarted mid-turn, that interrupted turn re-runs on resume (2.1.216+), so guard that turn's writes first. <!-- github.com/anthropics/claude-code/releases/tag/v2.1.216, checked 2026-10-15 -->
