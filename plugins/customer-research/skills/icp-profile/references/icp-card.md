# Ideal customer profile card

The profile describes accounts (companies), not people. Every line is marked **Backed (ids)** or **Assumption**.

| Field | Content | Status |
|---|---|---|
| Industry | | |
| Size band | | |
| Region | | |
| Business model | | |
| Trigger that makes it urgent | | |
| Current workaround | | |
| Who feels the pain (role) | | |
| Who pays (role) | | |
| Signals visible from outside the company | e.g. the company is hiring for a role, the tools it uses, a recent funding or growth event | |
| Why accounts stay or grow | tenure, renewals, expansion, revenue band of the accounts that retain | |
| Deal-breakers | | |

## Assumed vs evidenced

When the user names a target customer, print both side by side:

| | Assumed by the team | Evidenced by the data |
|---|---|---|
| Size | early-stage startups | 20–80 person agencies (S02, S05, S07, S09) |

This is the gap between the customer the team wants and the customer who pays.

## Anti-profile

Accounts that look similar but churn or do not buy. Every anti-profile line cites churn (C…) or lost-deal (L…) ids.

## Words customers use

Verbatim phrases by id, for the team to reuse later.

## Gaps

Fields with no evidence, each turned into a question for the next research round. They go here, not into empty rows of the card.

## Never

- Signals about a named person, or a list of people to contact.
- A profile without the Backed/Assumption column.
