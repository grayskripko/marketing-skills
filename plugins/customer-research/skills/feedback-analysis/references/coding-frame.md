# Coding frame for short feedback

Use for reviews, support tickets, open survey answers and score comments the user pastes or attaches.

## Build the frame

1. Default: read about 30 usable independent items, all if fewer. Use a stratified sample across supplied decision-relevant channels, plans and segments; increase beyond 30 if needed to cover them. State sample size and coverage used. Code all usable items after defining the frame.
2. Define the frame before coding everything: code, a default one-line definition and 1 example id. Use a longer definition plus supporting and contrasting example ids when the supplied items reveal an ambiguous boundary that changes counts; state that boundary. Print it only when requested or needed to resolve category ambiguity.
3. Default: up to 3 issue codes per item and expand/recode when unmatched other >10% of usable items. Use all explicit distinct issues when an item contains more than 3; count that item once per theme. Expand below 10% when unmatched records share a distinct issue with documented consequences material to the decision. State code-cap exceptions and recoding trigger used; recode all usable items with the final frame. If other exceeds 10% but contains no coherent new issue, retain it with its count and heterogeneity; do not invent a code to satisfy the threshold. Review even one unmatched distinct consequential issue below 10% when it affects the requested decision.

## Output components

Select only components needed for the requested deliverable: theme counts with ids, requested ratings and plan/segment comparisons, representative evidence and decision-relevant skew. A coding frame, complaint-type table or alternatives list is optional. Include a separate non-complaint row when comparing all usable records. Label all-item and complaint-only denominators distinctly; show neutral items’ effect on averages when material. Keep distinct needs separate and explain a misleading merged bucket when it changes the ranking.

## Long-item check

Check whether repeated or long text exaggerates independent demand. Count each independent item once per theme. A qualitative warning is sufficient unless exact text shares improve the decision; if printing them, state the word-count unit, usable denominator and exclusions and verify the totals. A single long item can also distort text volume.

## Source bias

A run of complaints is not a rate. Explain source bias only where it changes the requested interpretation.

## Churn and switching mentions

Include cancellation or switching evidence when relevant to the request, with ids. A previous-tool mention alone does not establish cancellation or require churn analysis.
