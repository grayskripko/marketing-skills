# Magnet readout

Answer the user's question in the first sentence (which magnet, whether the target was met), then one compact table with the counts, rates and costs, then a few lines on limits.

- Use the user's metric exactly as defined, numerator and denominator. Do not swap in a different metric. Label every rate with its denominator ("% of confirmed sign-ups", not "% of sign-ups").
- When recent sign-ups have not had time to convert, compare like with like: rates on cohorts old enough to convert, and say how far the recent cohort could move the result.
- Arithmetic exact; show the formula for the number the decision rests on.
- In one line each, flag only the definition problems that change the answer: booked versus held calls, sessions versus unique visitors, denominators that do not match.
- Compare magnets within the same traffic source when sources differ, and say how the mix changes the overall picture.
- Small counts: say plainly the verdict is provisional. If the user frames conversions as independent yes/no trials or asks whether a shortfall could be noise, give the 95% Wilson interval and how many more conversions, at the same traffic, reaching the target would take. Otherwise no tests, intervals, projections or thresholds.
- Say what the data shows, not causes it cannot show. When the data is unusable, say exactly which fields the replacement extract needs.
