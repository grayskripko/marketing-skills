# Knowledge check rules

A written check that the rep knows what the user's own material says. Retrieval practice (answering from memory) produced better delayed recall than re-reading the same text in Roediger and Karpicke (2006), so the check is a set of questions built to be retaken, not a summary to read.

## Source lines

1. Split the material into numbered source lines S1, S2 and so on: one fact, rule, price or limit per line, in the user's wording.
2. Print the source-line table before the items, so every key can be checked.
3. Long material: number only the sections the user wants covered and say which were left out.
4. Material with no clear facts (a vision statement, a slogan list): say so and ask for pricing, packaging, product limits, process rules or an answer sheet.

## Items

- 10 to 20 items; default 10 when the user names no number.
- About 40% recall ("What is the minimum number of seats on Pro?") and about 60% scenario ("A buyer wants 8 seats. What is the lowest compliant annual offer?"). Ratios are heuristics.
- Multiple choice with 4 options or short answer. Scenario items may chain two or three source lines.
- Wrong options come from plausible confusions inside the source: a neighbouring plan's price, monthly instead of annual, list instead of floor, a limit read as a default. Never from outside facts.
- Each item lists the S-lines that answer it.
- Mark critical items when the user says which facts a rep must never get wrong (prices, legal limits, security answers); otherwise ask once at the end.

## Source gaps

A question a buyer would plausibly ask whose answer is not in the material goes to a "source gap" list with a one-line reason, including any such question the user asked for. It is never answered, guessed or turned into an item. The list is part of the deliverable: it tells the user what their material is missing.

## Answer key

Item → correct answer → S-lines → one-line reasoning with every arithmetic step. The key is printed after the items, under a separator, so the user can hand out the items alone.

## Pass rule (heuristic, editable)

Pass = at least 80% of items correct and every critical item correct. Compare before rounding: 10 items need 8; 12 items need 0.8 × 12 = 9.6, so 10.

## Re-test schedule (heuristic, editable)

The same items, reshuffled with the options re-ordered, at about day 2, day 7 and day 21 after the first attempt; items missed earlier come first. Basis: spacing studies (Cepeda et al., 2006, a review of distributed practice; Cepeda et al., 2008) found that spreading study sessions beats massing them, and that the most useful gap grows with how long the material must be remembered. The exact days are this plugin's default, not a finding of those papers.

## Worked example

Source:
- S1 Pro plan: $40 per seat per month.
- S2 Pro is billed annually only.
- S3 Pro needs at least 10 seats.
- S4 Largest discount: 15% off list.

Item: "A buyer wants 8 seats on Pro. What is the lowest compliant yearly price?"
Key: 8 seats is below the minimum, so the offer is for 10 seats (S3). List = $40 × 10 × 12 = $4,800 a year (S1, S2). Largest discount 15%: $4,800 × 0.85 = $4,080 (S4).

Source gap: "Is single sign-on included?" The material does not say.
