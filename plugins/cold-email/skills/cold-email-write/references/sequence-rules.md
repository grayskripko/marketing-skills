# Sequence rules

All numbers here are heuristics of this plugin.

- Default to at most 5 steps per sequence; honor explicitly requested variants separately. Suggested business-day offsets: 0, 3, 7, 12, 20.
- Word targets: first email 50 to 125 words; follow-ups 30 to 80; the close 20 to 50.
- Each step stands on its own: a reader who missed the earlier emails still understands it.
- Each follow-up must serve a justified purpose. Default to a reason absent from earlier steps; an honest, limited reminder is allowed when appropriate to context. When the user explicitly requires new value at every step, satisfy that requirement or state the missing evidence; a reminder or close does not count as new value. Rewording a mechanism or repeating an asset is not new evidence. Compare each follow-up with its initial email and earlier follow-ups internally, then replace repetitions with an unused supplied fact or stakeholder angle. Do not invent asset contents, origins, requirements, workflow ownership or results to create novelty. If the supplied material supports no further reason, end with an honest close rather than filler. A close offers closure and is not counted as new proof. Purposes to choose from, one per step:
  - Problem: the pain in the buyer's words and the mechanism.
  - Proof: one specific result or reference from the user's facts.
  - Angle: a different stakeholder's view of the same problem.
  - Resource: something useful the user actually has (a checklist, a short teardown).
  - Close: a polite last note that leaves the door open and says no more emails will follow.
- One clear primary next step per email, with effort appropriate to context. Default to a brief permission ask; permit a justified meeting or routing question. Repeat the ask only when doing so remains useful and clear.
- Default to lightweight first-email copy and one primary offer destination; assess additional assets for recipient value, trust and size. Exclude required footer links from the discretionary offer-link budget.
- A reply of any kind stops the sequence for that person. For a request to stop, tell the user to add the contact to their suppression list; do not modify a list or claim the update is complete.
- Merge fields get a written fallback ("there" for an empty first name) or are left out.
