# Funnel leaks

First name, in one line, the user fact that most constrains the answer and how it changes the call; build the answer on it. Then which step or segment to prioritise and what it is worth, in the user's numbers.

- Check the counts agree first (a later step larger than an earlier one, segments that do not sum to the total, rates that do not match counts); an inconsistency is the headline. Then compute each step rate and show the arithmetic once.
- Stay inside the scope and output shape the user set.
- When periods differ, check whether segment rates moved or only the traffic mix did; if rates held, say the mix explains the drop and point at the traffic change, not at a redesign.
- Size stakes against the reference the user gave, actionable target first, then any stronger segment or earlier period, as "at unchanged volume, not a forecast". Show the resulting totals. No ceilings or caps the data does not show.
- Keep the user's real goal in view (completed versus qualified signups, orders versus paid orders).
- Next step: what to inspect or observe at that step to find the cause, and how to confirm a fix worked (the step rate to watch). Do not list speculative causes. Add test sizing only if the user asks about testing.
- No industry benchmarks as targets.
