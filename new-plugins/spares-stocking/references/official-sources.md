# Sources for spares stocking rules

Every page below was opened and read on 2026-10-13. The package makes no network requests at run time; these notes were embedded when it was built. System behaviour can be changed by configuration; the user's own system settings and approved stocking policy decide.

## 1. SAP reorder point planning

https://help.sap.com/SAPHelp_46c/helpdata/EN/f4/7d256344af11d182b40000e829fbfe/content.htm — read 2026-10-13. SAP R/3 4.6C help, "Reorder Point Planning". Procurement is triggered when the sum of plant stock and firmed receipts falls below the reorder point. The safety stock is included in the reorder level. In manual reorder point planning the MRP controller enters reorder level and safety stock in the material master; in automatic planning both come from the integrated forecasting program.

https://learning.sap.com/courses/consumption-based-planning-and-forecasting-in-sap-cloud-erp/using-forecast-in-reorder-point-planning — read 2026-10-13. SAP Learning, current course for SAP Cloud ERP, page undated. Reorder point = safety stock + average daily requirements × replenishment lead time. The safety stock is part of the reorder level. Procurement is triggered when stock plus firm receipts falls below the reorder point.

https://learning.sap.com/courses/consumption-based-planning-and-forecasting-in-sap-cloud-erp/answering-some-key-questions — read 2026-10-13. Reorder point procedures usually do not include requirements: sales orders, dependent requirements and reservations are not included in the net requirements calculation. Standard MRP types VB (manual) and VM (automatic) work without external requirements; V1 (manual) and V2 (automatic) include them, controlled by the "Include external requirements" indicator in Customizing of the MRP type.

https://help.sap.com/SAPHelp_46c/helpdata/EN/37/8bbbd26a8111d3b4ed0004ac160649/content.htm — read 2026-10-13. SAP R/3 4.6C help, "Reorder Point Planning with External Requirements". By default, sales orders and manual reservations are included in planning during the replenishment lead time; settings can extend this to the whole horizon. Without the indicator the system only displays them to inform the MRP controller.

https://help.sap.com/doc/95adce5314894208e10000000a174cb4/700_SFIN3E%20006/en-US/5997b6535fe6b74ce10000000a174cb4.html — read 2026-10-13. SAP help, version 700_SFIN3E 006, "Reorder Point Planning Procedure", page undated. Net requirements: the system compares plant stock (safety stock included) plus firmed receipts — purchase orders, production orders, firmed purchase requisitions and so on — with the reorder point; a shortage exists when the sum is below it. So stock 1 plus a firmed requisition for 2 against reorder point 3 is not below the reorder point in this calculation, while physical coverage by a work-order date is still open. Not checked for every current SAP release.

Not read: https://help.sap.com/docs/SAP_S4HANA_ON-PREMISE/af9ef57f504840d2b81be8667206d485/5697b6535fe6b74ce10000000a174cb4.html (SAP S/4HANA 2025 FPS01 help, "Reorder Point Planning"). On 2026-10-13 the page returned only a script shell to both a fetch tool and curl, so its text was not read directly. The current SAP Learning pages above state the same rules.

## 2. IBM Maximo reorder

https://www.ibm.com/support/pages/node/1131219 — read 2026-10-13. IBM Support, IBM Maximo Asset Management, undated. Order quantity = (reorder point + 1) − quantity on order − available balance; divided by the economic order quantity (EOQ), rounded up to the next whole number, times EOQ. Worked example: available balance = current balance − reserved quantity − expired quantity; quantity on order = open PR + PO quantities. Example: reorder point 20, EOQ 5, balance 10 → 11 → 15; a 200-unit reservation on an approved work order raises it to 215.

https://www.ibm.com/support/pages/node/1133109 — read 2026-10-13. IBM Support, IBM Maximo Asset Management, undated. Reorder creates PRs or POs to replenish storeroom stock; reserved quantity is reserved by work order, asset or location; quantity on order covers open PRs and POs; additional lead time days are added to the vendor lead time.

The statement that a reorder point of 0 still reorders when available balance plus stock on order drops to 0 comes from the abstract of https://www.ibm.com/support/pages/node/727797 (IBM Support, modified 17 September 2025), whose full text needs an IBM login and was not read. The skills use it only to explain the "at or below" trigger, which the order-quantity formula above (ordering up to reorder point + 1) also implies.

https://www.ibm.com/support/pages/node/7252100 — read 2026-10-13. IBM Maximo Application Suite Manage Operator patch 9.1.6 (Manage 9.1.283), released 27 November 2025, page modified 30 March 2026. APAR DT450390 ("Reordering Direct Issue items does not create a PO"), behavioural change: for condition-enabled items with a direct issue request, the condition code with condition rate 100 is added as the default on the planned material line (WPMATERIAL), and reorder uses it for direct-issue PRs and POs. Consequence: a requirement for one condition is not shown as covered by an aggregate balance of another condition without the user's acceptance evidence. Rate 100 is not necessarily a code literally named NEW, and the note does not show that a given installation has the defect.

## 3. Oracle Fusion Cloud Inventory min-max planning (26B)

https://docs.oracle.com/en/cloud/saas/supply-chain-and-manufacturing/26b/famml/how-min-max-planning-replenishment-quantities-are-calculated.html — read 2026-10-13. Oracle Fusion 26B manual, undated. A new order is suggested only if total available quantity < minimum quantity (strict). Order quantity = maximum quantity − total available, then raised to the minimum order quantity, lowered to the maximum order quantity, and revised to a multiple of the fixed lot multiple. At subinventory level, total available = on hand + on order (− open demand when any net demand option is Yes). On order = open POs, purchase requisitions and subinventory transfer movement requests scheduled for receipt at that subinventory on or before the supply cutoff date; supply referencing a different subinventory or none is excluded. Open demand counts reservations and movement requests from that subinventory by the demand cutoff date; reservations with a different or blank subinventory are excluded. Consequences: equality with the minimum does not trigger; a PO with no destination subinventory does not cover that subinventory's planning balance; available 2, inventory maximum 12 and maximum order quantity 6 gives an order of 6, not 10, absent other modifiers.

https://docs.oracle.com/en/cloud/saas/supply-chain-and-manufacturing/26b/famml/how-rounding-the-reorder-quantity-affects-min-max-planning.html — read 2026-10-13. Oracle Fusion 26B manual, undated. With a fixed lot multiple on the item subinventory, the inventory organization's Round reorder quantity parameter rounds the reorder quantity up when enabled and down when disabled: 24 with multiple 10 becomes 30 or 20. A suggestion of 20 can be the configured result even though it leaves the target unmet. A user's own pack-rounding policy overrides this.

## 4. OEM storage readiness

https://www.se.com/uk/en/faqs/FA337087/ — read 2026-10-13. Schneider Electric FAQ FA337087, published 2018, modified 17 April 2026. Altivar Process ATV600/ATV900: if the drive has not been connected to mains for 12 months at a maximum storage temperature of 50°C, 24 months at 45°C or 36 months at 40°C, the capacitors must be restored (one hour on line voltage) before the motor is started; at first commissioning, a manufacture date more than 12 months in the past invokes the same procedure. Consequence: an 18-month unpowered drive stored at up to 50°C is conditional coverage pending restoration evidence. Not transferable to other Altivar families; age alone does not justify disposal. The OEM procedure governs execution.

## Rules of thumb of this plugin (no external source)

- Usable stock is unrestricted, serviceable stock; quality-inspection, blocked, damaged, expired and awaiting-repair stock is shown separately. Whether a given system counts any of these as available depends on its configuration.
- Scheduled open supply is kept apart from received, released usable stock; coverage that depends on it is conditional. A past-due unreceived PO line is reported as stale. Whether a system's planning counts requisitions is a separate question answered by its documented rules (§1–§3).
- Look-alike part numbers are never linked automatically; supersession, interchangeability and unit conversions are used only when the user supplies them.
- Zero issues during stockout periods, and zero issues on a critical insurance spare, are not evidence of zero need.
- Sparse demand: coverage is computed with a Poisson assumption, P(D ≤ k) = Σ e^−λ λ^i / i!, where λ is mean lead-time demand. This is standard probability; the choice of Poisson for single-unit, independent, infrequent issues is this plugin's default and is stated in each answer that uses it.
- With unit issues, a reorder point R reorders at position R − 1 under a "falls below" trigger (SAP) and at R under an "at or below" trigger (Maximo); coverage is computed at that position.
