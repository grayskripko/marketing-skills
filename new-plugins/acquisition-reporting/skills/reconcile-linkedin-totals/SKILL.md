# Reconcile LinkedIn totals

Answer the requested reporting question first, in the requested format. Use a reconciliation table when requested or when multiple measures need comparison; otherwise give a compact calculation or decision. Include client wording only when requested. Weave metric labels, scope and any deciding missing evidence into that answer.

## Work from supplied evidence

1. Inventory exact headings and units, inclusive dates, timezone, reporting level, filters and extraction time for each input. Capture conversion action name and category separately (Lead is a category, not an inferred action name), data source, associated ad sets, attribution model, click/view windows and effective dates.
2. Match stable IDs before names. Preserve UI names and API field names; do not silently rename API CAMPAIGN to a current UI level. Establish the mapping from supplied exports. Separate conversion actions, form submissions, website conversions, qualified leads, viral metrics and unique people. A named action’s settings do not establish that an aggregate Conversions column contains only that action. Label totals action-specific only when the export or explicit supplied scope establishes it; otherwise retain aggregate labels and ask for the conversion-action breakdown if it matters.
3. Sum detail rows once. Exclude their subtotal/total rows from the sum; compare them separately. Detect repeated files, overlapping periods and overlapping breakdowns. Preserve fractional precision, blanks and displayed rounding. A blank is unknown unless the export definition establishes zero.
4. Compare only compatible populations and periods. Label a numerical gap between unlike metrics as a comparison of measures, not missing leads. Show signed difference = first total − second total. Explain each-ad-set credit when the settings establish it, but do not assign the entire gap to that mechanism without overlap evidence. A CRM contact total is not automatically the same population.
5. Separate demonstrated causes from possible factors. Do not infer tracking failure, lost leads, duplicate people or incremental impact from a gap. Use dated settings for historical reports. For unresolved scope, identify the smallest matching export or pasted table needed; never demand an export of the Attribution Model view.
6. Recommend the metric matching the reporting question: the Attribution Model view's direct Leads for LinkedIn Lead Gen Form submissions, labeled attribution credits for attribution contribution, verified deduplicated records for unique people. Keep both measures where they answer different questions. For qualified-lead cost, spend ÷ qualified leads needs a known, nonzero denominator.

## Incomplete API exports

An empty `elements` array can mean no activity or no read access; it does not prove zero. A report stops at 15,000 elements and has no pagination. At the cap, label completeness unverified, not proven incomplete. Request narrower non-overlapping date or entity extracts, subdividing until each is below the cap, with coverage of the intended scope and a matching account control total. A below-cap extract alone does not prove complete scope coverage. Professional demographic results suppress fewer than 3 events, return top 100 values per creative/day, can lag 12–24 hours and are approximate; do not use their sum to force an account total. Preserve export errors as missing-data evidence: 403 USER_NOT_AUTHORIZED means access/permission failure; 400 DATE_TOO_EARLY means outside retention; 414 REQUEST_URI_TOO_LONG means the request URI is too long; query tunneling is the documented remedy. A shorter request or smaller ID batches may also resolve the length problem; ask for a successful replacement covering the same intended scope. Do not request tokens or make API calls.

## Deciding knowledge

Apply these sourced rules only to the matching view, field or setting. In the answer, distinguish documented platform behavior from supplied account evidence. Fixed data-driven windows are not the supplied action's click/view windows. Include windows or reporting delays only when they resolve the user's question; do not use elapsed time alone to explain a gap.

- In the Campaign Manager Attribution Model view, Leads counts LinkedIn Lead Gen Form submissions, not website forms or unique CRM contacts. For a generic pasted Leads column, retain its label until the supplied heading/view or field mapping establishes this definition. Leads (data-driven attribution) credits funnel contributions over 180 days; filtering ad sets can include contributions to leads submitted elsewhere in the account. Conversions (data-driven attribution) uses a 90-day window for Insight Tag, Website Actions and Conversions API sources. Do not substitute conversion-rule windows for these fixed windows.
- Data-driven metrics can take 36 hours, rarely longer. Leads updates in real time. For an additional account-wide comparison, clear filters and use a range ending at least two days before extraction. Keep the requested scope and period in the main report. Treat freshness as a possible factor, not a quantified cause. The Attribution Model table cannot be exported: accept pasted headings, rows and totals.
- Last touch - Each ad set credits every associated ad set with an eligible interaction. Last touch - Last ad set credits the most recent eligible ad set. A sum of each-ad-set conversion credits is not a unique-person count; subtracting these attribution-credit totals does not establish overlap between people.
- For most conversion categories, repeated events count once per member, conversion action and ad set within the lookback window; Purchase and Add to Cart can count repeated events. Counting within one ad set does not remove eligible credits in another associated ad set; retain the supplied Each ad set or Last ad set attribution setting. Click and view windows are separate. Allowed ordinary windows are 1, 7, 30 or 90 days. CAPI/CSV allows 180 or 365 days for Submit Application, Purchase, Add to Cart, Qualified Lead, Marketing Qualified Lead, Sales Qualified Lead and Lead categories. Window changes affect future counting, not historical totals. Use supplied settings and dates; never assume a default.
- Modeled conversions are included in ordinary conversion metrics, not an extra count to add. This platform rule does not establish that a particular supplied total contains modeled conversions; without a breakdown, remove a claimed modeled add-back without asserting a modeled share or presence. Data-driven attribution and modeled conversion measurement are different concepts. Exports do not expose a modeled share merely because their totals differ.
- API `oneClickLeads` is One Click Lead Gen leads; `qualifiedLeads` is advertiser-shared qualified leads. `externalWebsiteConversions` counts website actions after clicks/views, potentially with group attribution or estimation. Preserve these labels; do not equate them to every UI lead column without supplied mapping. API dates are inclusive and UTC. Retain viral fields separately from paid fields.

## Worked example

Fictional Larch Harbor Studio supplies two selected ad sets, Lead-category action, Each ad set credit, same period and mature extraction. Standard conversions: 14 and 9. Data-driven conversions: 11 and 7. No overlap records.

Example output: “Standard conversion credits: 14 + 9 = 23. Data-driven credits: 11 + 7 = 18. Gap: 23 − 18 = 5 credits. Each-ad-set settings allow one conversion to receive credit in several ad sets. These aggregates do not establish five duplicate people or 18 unique people. Report the measures separately.”
