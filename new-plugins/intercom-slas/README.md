# Intercom SLAs

Explain why an Intercom SLA was missed and why report percentages disagree. Reconstruct chat and ticket targets from supplied events, settings and exported rows.
Choose history reconstruction or report interpretation; supply the inputs for that skill. For support operations teams investigating SLA clocks and report results. Bring pasted text or local exports, target settings and timestamps; analysis needs no account, keys, paid API or install beyond the host's skill loader.

| Skill | Supply | Receive |
|---|---|---|
| intercom-sla-history | Workflow conditions and Apply SLA steps, target definitions, chronological events, office hours, holidays and pause settings | Target-by-target history with clock anchors, replacements, pauses, deadlines and outcomes |
| intercom-sla-report | SLA dataset rows, chart metric name, time anchor, date range, timezone and filters | Row interpretation, counted units, denominators and explained discrepancies |

Ask “Why did this SLA start before the workflow?” or “Why is this target fixed rather than hit?” Keep customer and teammate events distinct. For deadlines include the schedule effective when the target was calculated, schedule changes, reapplication or override events, stored due times, timezone, enabled pause settings and relevant pause intervals. For dashboard comparisons include the chart information panel, not just its title.

Phone Speed of Answer rows are separated from chat/ticket calculations. Phone timers start at call connection and require a separate analysis.

The package contains instructions, embedded official knowledge and a neutral clock icon. Source URLs and observation dates are in [references/sources.md](references/sources.md). It analyzes supplied material; exporting or pasting data is the input path. Account access, monitoring, reply drafting and workflow changes are separate jobs.

## Data and network

Network fetches: none during skill use. The embedded references are local; documentation URLs are citations, not instructions to fetch. Only user-supplied text and files are read. No telemetry, service, connector or plugin-managed storage. Redact contact details and use stable object aliases when sharing exports. The host may use local code to calculate durations and rates.
