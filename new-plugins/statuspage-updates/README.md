# Statuspage Updates

Draft the next customer-facing outage update from your timeline, affected components and confirmed recovery evidence, with a justified Statuspage state.
For incident responders and support teams preparing customer communications.
Needs pasted notes or readable exports, component names and recovery evidence. No account, key, paid API or installation beyond loading the skills is required.

- **draft-incident-update** prepares the next active-incident title, state, message and affected-component choices.
- **check-incident-recovery** checks a proposed closure against supplied evidence and returns corrected Monitoring or Resolved copy, or an earlier state when warranted.

Paste the latest timeline with time zones, customer impact, confirmed cause, mitigation or fix, component states and any approved next-update time. For closure, include recovery observations for every affected component and any remaining symptoms. Redact credentials and personal details. A missing fact stays a short marker or question.

The package fetches no URLs and makes no network requests at runtime. It reads only supplied text and files. References bundle official Atlassian rules checked on 2026-10-11. It produces drafts in the conversation; publishing and notification settings remain actions in your Statuspage account.

Example requests: “Draft our next update from these incident notes.” “Can we call this resolved? Fix the closure copy from these recovery checks.”
