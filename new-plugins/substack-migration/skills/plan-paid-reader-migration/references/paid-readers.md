## Ghost native paid transfer

URL: https://support.substack.com/hc/en-us/articles/13547637301652-How-do-I-move-from-Ghost-to-Substack
Updated 2025-01-02. Members/Settings offers Export all members. List import alone creates free-status members. Payments/Connect with Stripe can use the existing Ghost account, not a newly created one. Enable Payments scans subscriptions; confirmation provides eligible counts. After revoking Ghost in Stripe Installed apps, the owner confirms disconnection and imports paid subscriptions. Completion arrives by email and is visible in Subscribers. Match actual account evidence; no universal eligibility inferred.

## Planning conventions and unknowns

Cohort tables, holding ambiguous dates, and comparing comp dates with prepaid coverage are authored preparation conventions. No checked page supplies an arbitrary per-row comp-expiration CSV schema, exact calendar rounding, transfer rules for every source, or a guaranteed match between exported paid counts and eligible native subscriptions. Never use generic Stripe migration advice as proof that Substack accepts a particular subscription. Verify current native terms and owner-approved cutover before high-responsibility account changes.

Use only the route needed for the supplied case. Keep source row IDs aligned with file names; preserve prepaid dates without adding an unsolicited menu of extensions. For Ghost, retain subscription/renewal evidence before revocation and follow the described native screen without inventing additional navigation labels. Verify the welcome-email preference; consent alone does not authorize a welcome message.
