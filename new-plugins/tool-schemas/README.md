# Tool Schemas

Fix AI agent tool contracts when connections work but tool choices, arguments or results fail. For developers and AI builders repairing an existing callable interface. Supply pasted traces, logs, configs, transcripts, tool definitions, handler code or selected files; artifact analysis needs no account, API key, install or paid service.

## What this package runs and connects to

This is a skills-only package of Markdown instructions and reference text, JSON metadata, a static SVG icon and a license. It bundles no executable scripts, dependencies, installers, hooks, MCP or LSP servers, or background processes. The `.claude-plugin` and `.codex-plugin` directories contain platform metadata, not runtimes. Installing it does not itself run a program or connect an account.

Pasted-artifact analysis uses only supplied material and bundled references: no code execution, web search, URL or robots.txt retrieval, dependency downloads, account connections, or remote tool calls. Source and support URLs identify references, not retrieval instructions. Paste relevant content rather than supplying a URL alone.

This package also supports requested execution and file changes through your assistant's existing tools. A requested repair of an owned local project may read and edit relevant implementation files and callers and run checks after inspecting commands and dependencies. An explicitly requested runtime check uses your selected installed runner, fixture, target, and existing authentication. It may call that tool/API endpoint and its documented backing service; local checks need no network. The actual endpoint and backing service depend on your supplied project, not a publisher endpoint. Requests disclose the call arguments and ordinary connection metadata to those destinations and the assistant's tool provider; check records may contain inputs and returned results. The skills do not request credential values, install software, download dependencies, or widen access. If a runtime/version is missing, they identify the prerequisite and can walk you through the project's existing setup; that setup may require user-run commands, so it is not an offline guarantee. Pasted definitions and receipts remain the no-setup fallback.

Checks use applicable stages in order: deterministic validation, live read-only calls, a documented no-send path, and a minimal real write only when required and authorized for the exact target and effect. A stage applies only when the selected interface provides it and it exercises the relevant behavior; unavailable required checks remain pending. Sending messages, deleting data, charging, or other real writes are possible only within that authorization; they are not part of artifact analysis. Existing receipts and actual state must be checked before retries.

The publisher receives no task data and operates no collection, telemetry, or storage service for this plugin. Your assistant provider processes conversations, attachments, tool activity, and temporary files under its own terms. Requested edits, output files, and check records use the assistant's existing tools and remain in your selected project; they are not created by a bundled program.

| Skill | What you ask for | What you get |
|---|---|---|
| tool-contract-audit | Explain the mismatch in this connected tool | Specific contract faults and replacement text or patch targets |
| tool-interface-repair | Fix this tool's choice and arguments | Schema, description and matching handler patch |
| tool-result-repair | Stop treating this error as success | Success, empty-result and error shapes with handler/consumer changes |
| tool-contract-check | Verify the repaired interface | Expected outcomes and observed PASS/FAIL checks |

Try “These two searches look identical; fix their definitions.” “Here is my strict function schema and rejected call; patch it.” “This handler says done when access fails; make the result explicit.” Or “Check this repair on the selected read-only fixture.”

A repair request with pasted code produces a concrete replacement or diff; audit and check requests produce the requested findings or verdicts. A request to fix an owned local project can use the host's existing file tools to edit relevant implementation files and callers. Runtime checks use the selected installed runner and existing authentication. If a runtime is missing, the agent identifies the project/version prerequisite and can walk through the project's setup; pasted definitions and receipts remain the no-setup path. Keep tokens, authorization headers and personal data out of shared artifacts.

The package contains instructions and references, with no bundled server or account connector. Check results identify the interface actually exercised: receipt review, direct handler, host exposure or agent choice. Connection startup belongs to MCP diagnosis; worker briefs belong to workflow repair; final report grading belongs to output evaluation.
