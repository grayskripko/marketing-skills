## Sources and deciding knowledge

1. https://docs.vllm.ai/en/latest/configuration/optimization/ — loaded. V1 preemption uses recomputation. Reducing sequence or batch budgets can reduce KV pressure. TP/PP changes trade memory against communication. Chunked prefill splits prompts and prioritizes decode. Latest describes --kv-cache-memory for repeating a measured allocation on unchanged hardware/free memory; verify installed syntax.
2. https://docs.vllm.ai/en/stable/configuration/engine_args/ — loaded. max_model_len covers input plus output; max_num_batched_tokens is per iteration; max_num_seqs is sequences per iteration. gpu_memory_utilization is per-instance executor memory; explicit kv_cache_memory_bytes is per-GPU KV storage and overrides it. Observed utilization default 0.92: never import this into unknown-version evidence. With installed support: max_num_seqs is also the checked default RUNNING admission limit; max_num_active_seqs caps RUNNING per engine while preserving runner/graph capacity; max_num_queued_reqs caps waiting plus running across DP ranks routed by one API server and rejects new arrivals with HTTP 503 at the limit; max_num_queued_tokens caps prompt tokens in prefill across that routing scope; full prompt length remains counted during partial prefill until transition out of prefill, including delayed prefix-hit accounting. New fields require installed-version confirmation. Human-readable numeric suffixes distinguish decimal lowercase k from binary uppercase K; preserve parsed values/units.
3. https://docs.vllm.ai/en/stable/serving/parallelism_scaling/ — loaded; .html redirects here. Cache log tokens represent simultaneous KV storage; concurrency divides by max_model_len. TP/PP distribute one replica rather than adding independent request pools. Rank repetitions cannot establish fleet capacity.
4. https://docs.vllm.ai/en/stable/configuration/optimization/ — loaded. V1 chunked prefill is enabled where possible; without it the documented budget must exceed context. The warning specifically identifies smaller budgets as startup failures. The checked stable scheduler validator allows equality; follow the installed-version validator. DP adds replicas; MoE layouts need their own topology interpretation.
5. https://docs.vllm.ai/en/stable/features/quantization/quantized_kvcache/ — loaded; .html redirects here. Use this official feature reference to verify KV-precision support for the installed backend before changing dtype. No-calibration FP8 uses scales 1.0; the documented per-attention-head calibration path requires Flash Attention and llm-compressor. Do not equate weight precision with cache precision.

6. https://docs.vllm.ai/en/stable/api/vllm/config/cache/ — loaded, read 2026-10-11. kv_cache_size_tokens is group-aware per DP engine; simple block-count multiplication can be wrong for hybrid caches. kv_cache_max_concurrency uses max_model_len. This also confirms explicit KV bytes precedence and the per-instance executor memory scope.
7. https://docs.vllm.ai/en/stable/api/vllm/config/scheduler/ — loaded, read 2026-10-11. verify_max_model_len rejects budget < context without chunked prefill; equality passes. max_num_seqs also serves as the checked default RUNNING admission limit, distinct from physical KV storage. It also rejects budget < max_num_seqs and max_num_active_seqs > max_num_seqs. This is more precise than the tuning prose. Check installed revision before using new fields.
8. https://docs.vllm.ai/en/stable/api/vllm/config/model/ — loaded, read 2026-10-11. max_model_len covers prompt and output. The observed auto/-1 option chooses a fitting length; it must not replace a user's fixed context requirement.

9. https://docs.vllm.ai/en/stable/design/hybrid_kv_cache_manager/ — loaded, read 2026-10-11. Design basis commit 458e74. Full-attention groups retain all tokens; sliding-window groups retain the recent window. Layer grouping and page/block layout govern allocation; raw global block multiplication cannot replace group-aware estimates. Use matching model/revision and group types, layer grouping, page/block and state/window parameters only when allocation logs cannot decide the target.

## Authored calculation and workflow rules

The floor(C/L), block-rounded reservation, per-replica minimum, deficit arithmetic, smallest-diff priority and same-workload restart comparison are authored analysis procedures, not guaranteed vLLM performance bounds. Apply only with the stated full-attention and reservation assumptions. No dense bytes/token estimate is provided for hybrid/MLA caches. No numeric safety margin is invented.
