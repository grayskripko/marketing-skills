# Project Profitability

Check which Harvest projects made money and explain differences between profit, invoices and budgets. Supply time, expenses, cost rates, project dates, fees, invoice totals and the allocation setting.
For agency owners, project managers and finance teams reviewing Harvest project margins.
Needs pasted text or readable CSV/Excel exports plus report settings. No account, key, paid API or installation is needed for the supplied-data workflow.

## What this package runs and connects to

This is a skills-only package of Markdown instructions and reference text, JSON metadata, and a static SVG icon. It includes no executable scripts, dependencies, installers, hooks, MCP or LSP servers, or background processes. Installing it does not run a program or connect an account. Development notes and evaluation records are also present in this working folder; they are not runtime components.

These skills analyze task text, attachments, and local files that you explicitly supply, plus bundled Harvest references. No executable code is bundled. Both skills permit your assistant's existing local calculation or code tool to compute totals from supplied material. Tool execution and any temporary files are managed by your assistant provider. A result is saved through the assistant's existing file tools only when you request it. The skills do not install software, connect to Harvest, call its API, send invoices or messages, publish content, or change account settings; account repairs are recommendations only.

The supplied-data analysis does not fetch URLs or search the web. Harvest source URLs identify the nine official help articles in each bundled reference register; the GitHub support URL identifies the publisher's issue tracker. A supplied URL is treated as text: paste the relevant content instead. Both reference registers also say to refresh sources before the planned 2026-10-19 submission. That preparation requires retrieving those listed public Harvest help pages; it is separate from analysis of your supplied data and is not an automatic process. Opening support or submitting an issue is a separate user action.

The publisher receives no task data through the plugin and operates no collection, telemetry, or storage service for it. Your assistant provider processes and may retain your conversation, attachments, tool execution, and temporary files under its own terms. Any output file you explicitly request is created by your assistant's existing file tools, not by a bundled program.

| Skill | Give it | You get |
|---|---|---|
| reconcile-project-profitability | Time and expense rows, project type, rate history, fees, dates, invoice totals, report period/currency and allocation toggle | Client/project gross-profit table with formulas and a bridge to the reported figures |
| diagnose-profitability-inputs | Missing-data notice, affected rows, billing mode, rate settings, project dates and budget settings | Field-level repair table with the affected scope and the next evidence needed |

Ask “Which projects made money this month?”, “Why does this fixed fee differ from our invoice?”, or “Which missing rates caused this warning?” Supply the exports in the conversation or select files the assistant can read. For line-level reconciliation, include all tracked time and expenses, both billable and nonbillable, not only uninvoiced items. Include extraction date, filters, currency and whether hours are already rounded. Project/client IDs are useful when names repeat; receipt images and contact details are unnecessary.

The Harvest report itself currently requires the Enterprise plan and Administrator permissions. Existing supplied data can still be reconciled. The instructions explain fixed-fee daily recognition and the supplied time-based/even allocation setting. Revenue with no eligible time remains unattributed. Currency totals stay separate. Missing inputs remain unknown.

## Data and network

Supplied-data analysis uses no network retrieval or account connector. Host calculation tools and requested output-file writes are permitted. The pre-submission public-source refresh is disclosed above. The package provides no account-editing or invoice-sending workflow and collects no telemetry.
