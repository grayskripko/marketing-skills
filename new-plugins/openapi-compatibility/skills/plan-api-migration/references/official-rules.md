# Official compatibility rules

Read 2026-10-11. Verification date is not a publication date. Use the version of each supplied contract. OAS latest resolved to 3.2.1 on this date; its document states publication 2026-09-10. Re-open this register's URLs before the planned 2026-10-21 submission and refresh changed rules. Living oasdiff/AIP pages provide no single release pin; the supplied tool build and policy determine its exported classifications.

## oasdiff — tool policy, not universal protocol rules

[Breaking-change catalog](https://www.oasdiff.com/docs/breaking-changes), read 2026-10-11; current live catalog, no publication date shown. Selected named entries: `new-required-request-property-with-default` and `response-required-property-removed` are Breaking; `request-property-removed` is Warning. Request enum narrowing and response enum widening are Breaking. These are directional classifications, not production traffic measurements. Response media-type removal and successful-status removal are Breaking; non-success-status removal is Info in this catalog. A withdrawn documented choice can still affect a consumer that relies on it; stronger response-field guarantees are a different kind of narrowing.

[Required request property with default](https://www.oasdiff.com/checks/new-required-request-property-with-default), read 2026-10-11. Default severity: error. Omission violates requiredness even if a server accepts it by fallback. Generated SDK signatures and gateway validation can also be affected. A severity file can use err/warn/info/none; an override changes classification, not the contract's accepted instances.

[Required response property removed](https://www.oasdiff.com/checks/response-required-property-removed), read 2026-10-11. Default severity: error. Consumers lose a guaranteed field. Its prose calls optional removal a warning, while the catalog and [optional-removal detail](https://www.oasdiff.com/checks/response-optional-property-removed), also read 2026-10-11, label that change informational. Preserve the observed tool version/configuration and report the conflict only when it affects a decision. Optional absence was already allowed, but presence-dependent business logic still needs investigation.

[Removal after deprecation](https://www.oasdiff.com/checks/api-removed-with-deprecation), read 2026-10-11: info. [Removal before sunset](https://www.oasdiff.com/checks/api-removed-before-sunset), read 2026-10-11: error. Continued callers lose the operation in either case; do not repeat the former page's blanket claim that existing clients are unaffected. Notice compliance and caller exposure are different questions. A deprecated flag does not establish a sunset date.

[CLI quick start](https://www.oasdiff.com/docs/getting-started), read 2026-10-11. `breaking` compares baseline then revision; documented result codes are 0 for no breaking changes and 1 for findings. `changelog` includes consumer changes beyond breaking findings; `diff` includes documentation edits. A numeric exit code without the command, successful execution and output does not establish compatibility. This package interprets exports and does not run or install this tool. Share-link upload options are outside its workflow.

## OpenAPI versions and effective contract

[OAS 3.2.1](https://spec.openapis.org/oas/v3.2.1.html), read 2026-10-11, published 2026-09-10; [latest pointer](https://spec.openapis.org/oas/latest.html), read 2026-10-11, resolved to 3.2.1. Relevant sections: 4.24.5 extended validation and 4.24.7 dialects. Format and directional annotations can require extended validation; `readOnly` differs from OAS 3.0. Schema dialect and actual validator behavior matter to compatibility. The spec describes contracts, not deployment behavior.

[OAS 3.1.2](https://spec.openapis.org/oas/v3.1.2.html), read 2026-10-11. Sections 4.8.10 Operation, 4.8.12 Parameter, 4.8.24 Schema and 4.8.30 Security Requirement: match method/path and resolved references; operation settings override applicable root/path defaults. Security objects in an array are alternatives; schemes within one object are jointly required. Empty operation security removes inherited requirements; an empty object allows anonymous access. Parameter identity is name plus location; serialization includes style/explode. An `operationId` is unique and can name generated client methods. Closed response schemas can reject newly added properties. These rules support both skills' effective-contract checks.

[OAS 3.0.4](https://spec.openapis.org/oas/v3.0.4.html), read 2026-10-11. Section 4.7.24.2: `nullable: true` takes effect only with a same-object explicit `type`; other constraints can still reject null. Required read-only properties apply to responses; required write-only properties apply to requests in this version. Do not carry that behavior blindly into newer dialects. Removing nullable from a request and adding it to a response have opposite compatibility effects. Translating type string + nullable true to types string/null may preserve accepted values; inspect surrounding constraints.

[JSON Schema Validation 2020-12](https://json-schema.org/draft/2020-12/json-schema-validation), read 2026-10-11; version pinned in URL. Sections 6.1.1 type, 6.1.2 enum, 6.5.3 required, 7 format, 9.2 default and 9.4 directional annotations. Requiredness concerns presence, not whether the value may be null. Default is an annotation, not automatic insertion. Enum and bound changes alter accepted instances; request restrictions and response expansion therefore need distinct analysis. Shared/composed schemas must be evaluated in context, not flattened as if every branch were an object-field merge.

## Google API policies — apply only to APIs using them

[AIP-180 Backwards compatibility](https://google.aip.dev/180), read 2026-10-11; living policy, no publication date asserted. Sections Guidance, Changing formats, Default values and Serializing defaults: removing/renaming existing components, changing static resource defaults, changing default-field presence or expanding an established format can break consumers. Dynamic defaults are outside the static-resource-default restriction; this does not establish their overall compatibility. Treat wire, source and semantic compatibility separately. These Google design requirements do not automatically bind unrelated REST APIs.

[AIP-158 Pagination](https://google.aip.dev/158), read 2026-10-11; Backwards compatibility section. Adding pagination to an existing collection method can be behaviorally breaking: callers expecting the whole collection receive a first page and fail to advance. Collection completeness and client method signatures need checks even when added fields appear structurally additive.

[AIP-203 Field behavior](https://google.aip.dev/203), read 2026-10-11; Backwards compatibility section, relevant compatibility guidance dated 2023-07-20 in its changelog. Adding REQUIRED to an optional field or adding a required request field is incompatible. Adding OUTPUT_ONLY to previously accepted input or INPUT_ONLY to previously emitted output is incompatible. Removing OUTPUT_ONLY from previously ignored input can also break consumers. These annotations can affect generated clients and are not interchangeable with OpenAPI required-response guarantees. Parent and nested-message behavior are independent, clarified in the 2023-09-14 changelog. Inspect supplied field-behavior annotations alongside OpenAPI constraints when present; do not manufacture annotations missing from an export.

## Planning rules authored for this package

Rule of thumb: prepare tolerant response readers before widening responses; prepare senders before enforcing stricter requests; verify replacement coverage before retiring a route. These are change-specific dependencies, not an asserted deployment order or mandatory notice duration. Mixed-version rollout and rollback require supplied topology and real consumer evidence. No default notice period, consumer count, adoption rate or tool version is assumed.
