# Plan a safe link repair

Analyze supplied evidence and read bundled references locally. Every Excel or file operation below is a step to recommend to the user or source owner, who performs it and reports observations; do not execute it yourself. For unavailable evidence, request only the relevant inspection result. Use the sections here as working guidance, not a required response template.

## Choose the repair

Use the supplied source, affected references, intended live-or-fixed outcome, platform and refresh state; ask only for a detail that changes the repair. Deliver a useful conditional plan if an outcome is missing. Avoid blanket Replace All, Break All, deleting unfamiliar names or redirecting a source to the destination itself. Do not change files; these are instructions the agent can walk the user through.

Windows/web entry point: Data > Queries & Connections > Workbook Links. Tell the user to select the affected source and use its options to reach Change source; wording may vary by release.

Choose the failure-specific repair before editing a path. The File Block, web refresh and named 3-D decisions below come from Microsoft pages read 2026-10-11; dated source notes are linked below.

Core Excel rules and repair decisions:
- Live data, source moved: Windows/web Workbook Links > source options > Change source repoints all references to that source. A single-reference edit affects only that formula. Confirm replacement workbook identity, sheet/name and cell meaning first. When mapped-drive and UNC routes are both supplied, prefer the confirmed UNC source as one target for both destination-opening routes and verify both; avoid a plan that alternates source settings between routes. Preserve anchors, quotes, functions and separators; a matching filename does not prove matching data.
- Name/formula target invalid: #REF! requires checking the intended cell/sheet, not just the path. INDIRECT referencing another workbook fails when that source is closed. Dynamic-array references to a closed source can also return #REF!. For a fixed-address INDIRECT, consider letting Excel generate a direct link by selecting the source cell with both files open; review the resulting anchors before copying it.
- Named 3-D case: confirm both source and destination are .xlsx, the source name spans sheets, the destination links to that name, and failure follows saving/closing both, reopening the destination and updating links. Microsoft documents avoiding that external named 3-D reference or saving both files as .xlsb. For live calculations, a confirmed ordinary source total cell can replace the named reference; preserve its sheet span and calculation. Have the owner recalculate and save that source total before refreshing a closed-source destination. Verify the actual sheet span and calculation against an independently confirmed expected result. When a controlled change is authorized in an isolated test copy, choose an input change with an observable expected effect, then have the owner recalculate and save the source, refresh/reopen the destination, restore the input and verify the baseline. Otherwise compare an owner-confirmed source result and state that change propagation remains untested. Default worked example only when the actual calculation is a SUM of twelve months of 100: changing one month to 101 should give 1201, then restoring it should give 1200 after recalculation, source save and destination refresh. Assess format compatibility before choosing .xlsb. Do not apply this diagnosis to .xlsm/.xlsb destinations merely because a name appears in the error.
- Web cross-domain/tenant/geography failure: refresh in desktop Excel with authorized source access. Do not promise that signing in again fixes the web limitation. Guide the user to open the authoritative cloud files in desktop Excel, refresh the destination, verify the current source value and retained formula, and save back to its cloud location; assess the reported results. For recurring use, establish who refreshes and saves the authoritative workbook and when. Retain the existing refresh-on-open preference by default; review it only if it conflicts with that workflow, and change it with the workbook owner's agreement. Manual refresh/save may be sufficient; updates require desktop refresh and saving, and are not continuous while desktop is closed. Do not offer a source copy as a live solution without an owner-maintained update arrangement.
- File-type blocking since October 2025: existing values can be stale while refresh fails; a new link can show #BLOCKED. Inspect the error detail and File Block settings. Recommend that the source owner produce a genuinely converted approved supported-format workbook, not a renamed extension, and validate it before relinking. Confirm that the owner will keep that replacement current; a one-time copy does not satisfy ongoing live rates. Use a replacement path only once supplied or clearly conditional. Do not prescribe registry edits or disabling protections.
- Fixed snapshot: Break links turns dependent formulas into current values. Desktop Microsoft guidance says it cannot be undone; web guidance allows Undo. Always preserve a separate original. Obtain explicit intent to freeze values; do not freeze stale or error values without a decision about that limitation. For a mixed confirmed/unconfirmed report, freeze confirmed cells selectively rather than breaking an entire source prematurely; record each frozen value’s source, confirmation and date. Keep local derived formulas where appropriate. Unconfirmed inputs and their results remain unknown unless the user accepts a clearly identified incomplete archive. Preserve confirmed query results and inspect their consumers before removing connections or parameters. Review dependent names and query parameters separately; breaking formula links is not proof of complete independence.
- Suppressing prompts does not repair references or prove freshness. Workbook refresh preferences affect its users. The Windows application setting “Ask to update automatic links” affects that computer and clearing it causes automatic updates; do not propose it as a safe cleanup.

Read [Microsoft reference notes](references/microsoft-links.md) for exact source scope. The backup, narrow-change and verification choices below are safety recommendations, not Microsoft guarantees.

## Inventory before changing sources

Use the supplied inventory to identify formulas, defined names, linked objects/charts and queries/connections affected by the requested change. Keep ordinary navigation hyperlinks in a separate list. For a query/connection source change, inspect its own definition and refresh controls; do not assume Workbook Links > Change source updates it. Record the expected target and data meaning before changing anything. A hyperlink target change affects navigation; inspect any external formula references in its arguments separately.

For a snapshot, state exactly which formulas become values, which accepted refresh state supplies those values, and which names, objects, query/connection dependencies or hyperlinks still need separate inspection. Preserve the original, explain desktop irreversibility and web Undo, and verify the intended remaining dependency inventory after reopening.

## Repair and verification guidance

Use only the steps relevant to the requested repair; integrate the necessary protection and expected observations into the answer rather than requiring this five-part report.

1. Preserve an unchanged separate original and note the source, current formula/name and any known last refresh. Make the narrow repair in the intended destination; use a working copy when the change warrants it, without requiring a separate copy-and-replacement workflow for a simple confirmed relink.
2. Give the smallest action with its scope and effect. Show before/after formulas only when replacement details are supplied; otherwise use a specific missing-detail marker.
3. Define expected observations before checking: intended source opens, repaired references target the correct sheet/name/cells, refresh completes, affected values match source inputs, and no new errors appear. For snapshots, confirm accepted values before converting and then check the intended references are gone; reopen with source access unavailable to verify that the archive’s required values, charts and retained query results still work.
4. Save and close the repaired destination, reopen through the intended access route, and repeat relevant link/name/chart checks. For live ordinary links, test the intended source-open and source-closed use; for INDIRECT/dynamic arrays state the known open-source dependency. A prompt disappearing alone is insufficient.
5. Report success only from user-observed results; otherwise describe the proposed action and the observations still needed, without a routine status label. Preserve remaining uncertainties without claiming whole-workbook coverage from excerpts.

## Worked example

Input: Willow Lantern Works moved Inputs.xlsx to an approved Reports folder. It needs live calculations; the source's Totals!B4 is confirmed unchanged.

Example answer:
> Keep an unchanged backup, then change the Inputs.xlsx source to the approved file using Workbook Links > Change source. This keeps linked formulas and repoints every reference to that source. Refresh, compare the affected cells with Totals!B4 and the other source inputs, then save, close and reopen through the normal folder route. Keep the original until those checks pass.
