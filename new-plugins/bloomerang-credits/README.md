# Bloomerang Credits

Reconcile Bloomerang raised and revenue totals from donation, pledge and soft-credit exports using the September/October 2026 rule changes.
For nonprofit finance and fundraising staff comparing Bloomerang CRM reports.
Needs pasted rows or CSV/Excel exports, report dates and filters, and donation-to-credit-to-pledge links. No accounts, keys or installation beyond the plugin are required.

## What this package runs and connects to

This is a skills-only package of Markdown instructions and reference text, JSON metadata, and a static SVG icon. It includes no executable scripts, dependencies, installers, hooks, MCP or LSP servers, or background processes. Installing it does not run a program or connect an account. The .claude-plugin and .codex-plugin directories contain platform metadata, not executable runtimes.

These skills analyze only task text, attachments, and local files that you explicitly supply, using bundled reference text. They do not direct software installation, web search, URL or robots.txt retrieval, API calls, account access, message delivery, publication, or settings changes during reconciliation or explanation. A supplied URL is treated as text: paste the relevant content instead. Bloomerang source links identify the embedded knowledge; GitHub links identify documentation or support pages.

This workflow is offline with respect to additional network requests, but it is not a strict no-execution workflow: your assistant's existing local calculation tools may read supplied exports and calculate totals, as the privacy policy previously permitted. No calculation code or installer is bundled. Any output file you explicitly request is created by your assistant's existing file tools, not by a bundled program. Tool execution and temporary files are managed by your assistant provider.

The source registers say to recheck the release notes before the planned 2026-10-19 submission. That is a separate maintainer task involving retrieval of the public Bloomerang release-notes page listed there, not a step in user reconciliation; it must not send supplied donor exports. Ordinary web requests disclose the requested URL and connection metadata to the site and tool provider. User workflows use the bundled text without retrieving these pages.

The publisher receives no task data and operates no collection, telemetry, or storage service for this plugin. Your assistant provider still processes and may retain your conversation and attachments under its own terms. The local development records in tests/, BUILD-NOTES.md and REVIEW.md are evaluation evidence, not runtime instructions; scanhold section 1 recommends keeping them outside the submitted release folder.

- **reconcile-bloomerang-totals**: produce raised/revenue contributions and reconcile supplied report totals.
- **explain-bloomerang-credit-changes**: explain September/October differences or a dated soft-credit validation error.

Include stable transaction and credit IDs, types, amounts, currency, dates, pledge links and whether each credit is applied. A label alone cannot establish the applied amount. Use anonymous IDs instead of donor names. Partial exports produce supported subtotals and unresolved rows.

The embedded official knowledge was checked on 2026-10-11. It covers the September 3 recalculation, October 8 removal of the soft-credit cap, unchanged revenue, report row types and export limits. Sources and dates are in each skill's references/sources.md.
