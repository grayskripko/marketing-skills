# Pinterest Publishing

Check this pasted RSS feed and tell me why Pinterest won't turn my articles into Pins.
For website publishers using Pinterest native RSS publishing. Bring pasted feed XML, an export, or a screenshot you describe; no account or setup is required for diagnosis. Connecting a feed requires a Pinterest business account, a claimed website, a hosted RSS URL, and desktop settings.

## What this package runs and connects to

This is a skills-only package of Markdown instructions and reference text, JSON platform metadata, and a static SVG icon. It bundles no executable scripts, dependencies, installers, hooks, MCP or LSP servers, or background processes. Installing it does not run a program or connect an account. The `.claude-plugin` and `.codex-plugin` directories contain platform metadata, not executable runtimes. This working folder also contains development notes, reviews, and text/JSON test evidence; those are not runtime components.

Pasted feed XML, exports, and described screenshots support diagnosis without retrieval, but these skills are not strictly offline or execution-free. Both skills permit the assistant's existing browsing tool to refresh official requirements at help.pinterest.com, create.pinterest.com, and policy.pinterest.com. Their reference notes also instruct reopening sources and consulting the RSS 1.0 specification at web.resource.org. Only when you request URL inspection may the assistant retrieve your public feed and the specific article/image URLs needed for diagnosis, their redirects, and robots.txt for every inspected host, including redirect hosts. Requests disclose the requested URLs and ordinary connection metadata to those sites and the browsing provider. Pasted task material is not directed to an external API or publishing service. If retrieval is unavailable, supply the relevant content; pasted XML cannot prove live reachability.

The feed-check skill also directs use of a safe local XML parser when a complete document and parser are available, with external entity and network resolution disabled. This uses the assistant's existing execution facility; no parser or installer is bundled, and no software installation is instructed. It can run even for pasted input, so a no-network diagnosis is not necessarily execution-free. Without parsing, the answer must not claim a completed parser test. Local execution and any temporary files are managed by the assistant provider.

The assistant returns proposed XML repairs and setup guidance; the skills do not instruct it to save repairs to website files, call a publishing API, send messages, connect accounts, or publish Pins. You apply website HTML-tag or root-file verification, DNS TXT changes, feed repairs, and Pinterest settings yourself. Saving a native RSS connection activates Pinterest publishing; stop before Save if you are not ready. User-side observation of a new eligible item is a validation plan, not a performed publishing test.

The publisher receives no task data and operates no collection, telemetry, or storage service for this plugin. Your assistant provider processes and may retain your conversation, attachments, and tool activity under its own terms. Source URLs can be retrieval destinations in the workflows above; repository and support URLs are references, not automatic upload destinations.

- **Check RSS feed:** whole-feed blockers and item defects, exact supported repairs, and setup steps when requested or relevant.
- **Set up RSS publishing:** website claiming and desktop settings, then timing and visibility troubleshooting.

No account connection, automatic monitoring, or publishing is included. The agent guides you through Pinterest settings. A pasted fragment cannot establish whole-feed validity or live reachability.
