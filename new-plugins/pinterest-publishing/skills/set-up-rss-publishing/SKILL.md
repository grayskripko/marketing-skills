## Native RSS facts that decide the result
Pinterest supports XML RSS 2.* and RSS 1.* (RDF), not Atom. Every item needs an article link under the user's claimed domain. Do not substitute an unrelated destination or assume a subdomain/subpath is covered without the supplied claim scope.
Images are taken from item-level `<image>`, `<enclosure>` and `<media:content>`; titles and descriptions come from item-level `<title>` and `<description>`. A channel logo is not an item image. Pinterest also says it can create Pins for multiple images in an item or webpage: absence of an item image is a repair opportunity, not proof that webpage discovery will fail. Do not impose an undocumented image dimension, byte limit, title limit or GUID requirement on native RSS.
Feed updates may take up to 24 hours according to RSS Help. Pinterest Create describes 24–48 hours when setting up RSS; for a new connection, distinguish that setup window from subsequent updates and do not promise a hard deadline. Oldest feed content publishes first. The documented ceiling is up to 200 Pins per day, not 200 articles. Multiple images can yield multiple Pins. Do not promise queue completion, backfill of content no longer in the feed, or republication after editing an old item. Feed count is unrestricted when feeds match the claimed website; each can target a different board. Secret-board publishing prevents public discovery; the owner can inspect their own board to distinguish hidden Pins from missing Pins.
Describe this desktop path for the user to perform in their own interface: business account → Settings → Create Pins in bulk → Auto-publish → Connect RSS feed → feed URL → Save Pins to (board) → Save. Explain that the user's final Save activates publishing; instruct them to stop before Save if they are not ready. Do not execute the connection or publishing actions yourself. Connect RSS feed appears only with a claimed website; mobile cannot connect it.
Error meanings: “RSS feed already exists” means keep the existing connection if that is the intended feed; use a different feed only to add another; “RSS feed cannot be fetched” means check public URL access; “RSS feed cannot be parsed” means check valid XML RSS; “RSS feed unknown format” means check supported RSS version; “Links in the RSS feed are not under the claimed domain” means check all item destinations against the claim.
Use native publishing only. Do not recommend duplicate-content flooding, redirects to evade domain or spam checks, or unauthorized automation. These boundaries come from Pinterest Community Guidelines, not a diagnosis of an unexplained failure.

## Guide setup and explain status
Use this skill for a missing RSS option, domain claiming, board visibility or processing delay. If malformed feed items are supplied, handle visible defects and use the feed facts above; do not invent an account diagnosis.
For a new connection, lead with the next action using supplied status; establish business account, desktop screen and website claim only as needed to explain that action. Use a checklist only when requested or helpful for several remaining actions. For an existing connection, lead with the supplied visibility, timing and cap facts; revisit prerequisites only when an error makes them relevant. A profile website link is not proof of a verified claim. Claim initiation may be Settings → Link to Pinterest → Claim next to Websites; existing claims may appear under Claimed accounts. Use the user's described screen to resolve menu variation.
The user must control the website/domain. A website can be claimed by only one Pinterest account; most marketplace shops cannot be claimed. Offer the available verification method: HTML tag in head, HTML verification file at server root, or DNS TXT. Have the user copy exact generated values inside their own interfaces, never into chat. TXT propagation may take up to 72 hours. Google Merchant Center claiming is only offered to some accounts; it is not a prerequisite.
Guide the user through the desktop native RSS path above. Use their specified target board and visibility; if missing and necessary for the next step, ask them to choose. Explain that their Save activates publishing and instruct them to stop before Save if they are not ready. For no-setup work, inspect pasted XML or their described settings screenshot and return remaining actions without claiming a connection.
Changing the feed destination does not establish that existing secret Pins move or republish. Check those Pins separately.
For an existing connection, compare update elapsed time to the 24-hour update window, considering the 24–48-hour setup wording if it is newly connected, and count potential Pins rather than articles. Check secret-board visibility separately from creation. State oldest-first ordering without guaranteeing an exact completion time. If the window has passed, request the exact error and an affected item rather than reconnecting blindly. After a simple single-feed, single-board repair, default to observing one naturally occurring eligible new item and recording title, board and elapsed time. For several affected feeds, boards or defect classes, choose representative items for each changed branch and record feed/item URL or identifier, relevant timestamps, expected and observed Pins/images, and any error. If no new item is available, check the supplied feed and connection evidence, leave ingestion unconfirmed and observe the next planned eligible publication; do not promise old-item republication. This is a user-side validation plan, not proof of publishing.

## Worked example
Fictional company: Pebble Loom Notes. User has a business account, a verified website, and connected RSS to a secret board four hours ago.
Example answer: “Check the secret board for the new Pins first. People on Pinterest cannot see Pins saved there. Four hours is still inside the setup window: Pinterest Create describes 24–48 hours for a new RSS connection, while RSS Help gives up to 24 hours for feed updates. If you want public discovery, select an appropriate public board in your native feed settings. Check existing secret Pins separately; changing the destination does not prove they move or republish. If no Pins appear after the applicable window, bring the exact error and one affected feed item.”
